Load `00-pm-academy-core` alongside this skill.

## 1. Why SEO Matters Here

The 90 lesson topics map 1:1 to real search queries:
- "what is a PRD"
- "jobs to be done framework explained"
- "product-led growth definition"
- "what is product management"
- "user story vs job story"

Public lesson pages targeting these terms are the **largest organic acquisition channel by month 6–12**. Treat every lesson page as a long-term SEO asset — the compounding effect starts from day one of being indexed.

    }
  }
  
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: JSON.stringify(courseSchema) }}
    />
  )
}

## 3. Static Generation vs. SSR

Lesson pages are **static** (generated at build time from static JSON), not server-rendered per request. This gives maximum performance and CDN caching.

```typescript
// app/(marketing)/lessons/[slug]/page.tsx

// ✅ CORRECT — generateStaticParams for build-time generation
export async function generateStaticParams() {
  // Read the lessons index (generated by the content pipeline)
  const index = await getLessonsIndex()
  return index.lessons.map(lesson => ({ slug: lesson.slug }))
}

// This makes lesson pages fully static — built at deploy time, served from CDN
// No per-request server computation for lesson content (which doesn't change between deploys)

export default async function LessonPage({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const lesson = await getLessonJSON(slug)
  return <LessonView lesson={lesson} />
}
```

**When to use `force-dynamic`:** Only for pages with user-specific data that changes per request (e.g., `(app)/dashboard`). Public lesson pages should never be `force-dynamic`.

**Rendering strategy by route:**

| Route | Strategy | Why |
|-------|----------|-----|
| `(marketing)/lessons/[slug]` | **SSG** (`generateStaticParams`) | Content doesn't change between deploys; maximum performance |
| `(marketing)/curriculum` | **SSG** | Static lesson list |
| `(marketing)/` | **SSG** | Static marketing content |
| `(app)/dashboard` | **Dynamic SSR** | User-specific data |
| `(app)/curriculum/[module]/[lesson]` | **Dynamic SSR** | User progress overlay on static content |
| `(portfolio)/p/[username]` | **SSG with fallback** or **Dynamic SSR** | User-generated; build-time generation not feasible |

## 4. Semantic HTML Rules

```html
<!-- CORRECT heading hierarchy — ONE h1 per page -->
<h1>What is a PRD? — PM Academy</h1>
<h2>Theory</h2>
<h3>What Makes a Great PRD</h3>
<h2>Common Mistakes</h2>

<!-- CORRECT semantic elements -->
<article>...</article>          <!-- Lesson content -->
<nav aria-label="Lesson navigation">...</nav>
<aside aria-label="Key Takeaways">...</aside>
<main>...</main>                <!-- Page main content — one per page -->
<header>...</header>
<footer>...</footer>
<section aria-labelledby="section-heading">...</section>

<!-- WRONG — div soup -->
<div class="h1-style">...</div>
<div class="article">...</div>
```

Rules:
- One `<h1>` per page — never zero, never two
- Logical heading hierarchy (never skip from h2 to h4)
- `<article>` for lesson content
- `<nav>` for navigation blocks with `aria-label`
- `<main>` wraps the primary page content

## 5. Sitemap & Robots

```typescript
// app/sitemap.ts
import { MetadataRoute } from 'next'
import { getLessonsIndex } from '@/lib/content'

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const index = await getLessonsIndex()
  
  const lessonEntries = index.lessons.map(lesson => ({
    url: `https://pmacademy.com/lessons/${lesson.slug}`,
    lastModified: new Date(),
    changeFrequency: 'monthly' as const,
    priority: 0.8,
  }))
  
  return [
    { url: 'https://pmacademy.com', lastModified: new Date(), changeFrequency: 'weekly', priority: 1.0 },
    { url: 'https://pmacademy.com/curriculum', lastModified: new Date(), changeFrequency: 'monthly', priority: 0.9 },
    { url: 'https://pmacademy.com/about', lastModified: new Date(), changeFrequency: 'monthly', priority: 0.5 },
    ...lessonEntries,
  ]
}
```

const nextConfig = {

            ].join('; '),
          },
        ],

## 7. Lighthouse Performance Targets

**Target: ≥ 90 on all lesson and marketing pages.** Design for this from Phase 1, not as a Phase 4 retrofit.

### Image Optimization
```typescript
// Always use next/image — never raw <img> tags
import Image from 'next/image'

<Image
  src="/hero.webp"
  alt="PM Academy skill radar showing 7 competency areas"
  width={800}
  height={600}
  priority  // Only for above-the-fold images
/>
```

### Font Optimization
```typescript
// app/layout.tsx — use next/font
import { Inter, Fraunces } from 'next/font/google'

const inter = Inter({ subsets: ['latin'], variable: '--font-body', display: 'swap' })
const fraunces = Fraunces({ subsets: ['latin'], variable: '--font-heading', display: 'swap' })
```

### Core Web Vitals
- **LCP (Largest Contentful Paint):** Preload hero image on landing page. On lesson pages, the `<h1>` is LCP candidate — ensure heading font loads fast (use `display: swap`).
- **CLS (Cumulative Layout Shift):** Always specify `width` and `height` on images. Use `min-h` on loading skeletons to prevent layout shifts.
- **INP (Interaction to Next Paint):** Minimize JS bundle. Server components reduce client JS. Keep client-only code small and lazy-loaded.

### Bundle Size
- Analyze with `ANALYZE=true npm run build` (add `@next/bundle-analyzer` if not installed)
- Keep client-side JS for lesson reading view minimal (it's mostly server-rendered)
- Framer Motion: import only needed components (`import { motion } from 'framer-motion'` is fine; avoid `import * from`)
- Lucide React: import individual icons (`import { BookOpen } from 'lucide-react'`), never the full package

## 8. Content SEO Strategy

### Priority Keyword Clusters (mapped to lessons)
Each lesson title should align with a real search query. Before writing lesson titles, verify:
1. Is this a query someone types in Google?
2. Does the title match natural language ("What is...?", "[Framework] explained", "How to write a...")?
3. Is there search intent alignment (informational for lessons, not transactional)?

### Curriculum Page as SEO Asset
`/curriculum` — publish the full 90-lesson, 9-module outline publicly (even pre-launch). This is:
- A credibility signal ("here's actual depth")
- A strong SEO asset (module/lesson titles = real search queries)
- Indexed by Google long before individual lesson pages rank individually

### Portfolio Export as Backlink Engine
`/p/[username]` pages linked from LinkedIn profiles = backlinks + referral traffic.
- Footer of portfolio pages: "Built with PM Academy" (subtle, branded)
- Ensure `<meta name="robots" content="index,follow">` on public portfolio pages

## 10. Pre-Launch SEO Checklist

Before going public:
- [ ] All 3–5 sample lesson pages have unique meta titles + descriptions (< 155 chars)
- [ ] Curriculum page is live and indexable (`noindex` NOT set)
- [ ] `sitemap.xml` generates correctly and is submitted to Google Search Console
- [ ] `robots.txt` blocks `/api/`, `/dashboard/`, `/review/`, `/progress/`, `/settings/`
- [ ] Structured data validates in Google's Rich Results Test
- [ ] No `noindex` accidentally on public pages
- [ ] Canonical URLs set on all public pages
- [ ] Open Graph images generate correctly (test in Facebook/Twitter/LinkedIn debuggers)
- [ ] Lighthouse ≥ 90 on lesson page and home page (real run, not simulated)
- [ ] Core Web Vitals passing in Chrome DevTools (LCP, CLS, INP)
- [ ] Google Analytics tracking public page views
- [ ] HTTP security headers returning correctly (`X-Frame-Options`, `X-Content-Type-Options`)
- [ ] `generateStaticParams` set on all lesson pages (verify static generation in build output)
