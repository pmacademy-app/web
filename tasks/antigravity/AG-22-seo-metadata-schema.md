# AG-22: Sitemap dates, valid schema and clean metadata

- **IDs closed:** plan PR-21 (SEO-06, SEO-07, SEO-08, SEO-09, SEO-10, AEO-05)
- **Milestone:** M2 Growth foundations
- **Depends on:** none (M1 does not block it; run after AG-18 if both touch marketing pages at once)
- **Size:** M
- **Parallel-safe:** yes with M1 backend tasks; no with AG-23, AG-24, AG-25 (same metadata files)
- **Needs owner action:** verify Google Search Console and Bing Webmaster Tools (free) and submit the sitemap after deploy

## Why
Every sitemap entry claims it changed today, so crawlers learn to ignore `lastmod`. The course schema uses an invalid type and labels 85 of 90 lessons "Advanced". These lower trust in the structured data that search and AI answers read.

## Current state (verified 2026-11-12)
- `apps/web/app/sitemap.ts:25-73` static pages and `:80-85` lessons all use `lastModified: new Date()`. Portfolios already use real dates (`:91-100`).
- `content/dist/curriculum.json` lessons have no date field (keys: `id, slug, title, module, order, difficulty, estimatedReadingTime, estimatedCompletionTime, prerequisites`).
- `apps/web/lib/schema.ts:86` `'@type': 'CourseUnit'` (not a schema.org type).
- `apps/web/lib/schema.ts:105-110`: difficulty 1 is Beginner, 2 Intermediate, anything else Advanced. Actual difficulty counts: 1:4, 2:1, 3:11, 4:23, 5:20, 6:20, 7:10, 8:1. So 85 lessons read "Advanced".
- `apps/web/lib/certificates.ts:75` emits `grantee`.
- `apps/web/app/layout.tsx:85-90` `twitter` metadata has no `site` handle (`BRAND` has `https://x.com/prodily_pm` in `apps/web/lib/brand.ts:13`).
- `apps/web/app/(marketing)/faq/page.tsx:13`, `:20`, `:36` titles say "Product Management Academy FAQ | Prodily".
- Organization `sameAs` and `@id`s already exist (`lib/schema.ts:20-55`). Glossary already 308s to `/frameworks` (`app/(marketing)/glossary/page.tsx`).

## Files in scope

Do not derive dates from git at build time: CI checks out with depth 1 and Vercel clones shallow, so every lesson would get the same date.

- `apps/web/lib/schema.ts`, `apps/web/lib/certificates.ts`, `apps/web/app/layout.tsx`, `apps/web/app/(marketing)/faq/page.tsx`, `apps/web/components/marketing/faq-explorer.tsx`

## Steps
1. Dates: create `content/lesson-dates.json` (initial values from `git log -1 --format=%cs -- content/lessons/<file>` on a full local clone; show the table in the plan for owner approval). Compiler reads it and emits `updatedAt`; a missing date fails the build with a clear message. Run `npm run test:compiler` and `npm run content:build`.
2. Sitemap: lessons use `updatedAt`; static pages use a committed date constant (for example in `apps/web/config/content.ts`) that you update by hand when the page changes, or omit `lastModified`; never a build-time date; drop any URL that redirects (check `/glossary`). Add public capstone pages (`app/(portfolio)/p/[username]/capstones/[moduleSlug]/page.tsx`) for public portfolios only, and only submissions that page would render publicly; reuse the portfolio entry query and its dates.
3. Schema: `hasPart` items become `Course` or `Syllabus` per current schema.org guidance (state your choice and source in the plan); map difficulty 1 to 3 Beginner, 4 to 6 Intermediate, 7 to 8 Advanced (confirm the bands with the user in the plan); add `datePublished`/`dateModified` to lesson `LearningResource`; remove `grantee`.
4. `twitter.site` from `BRAND`; remove duplicated brand words in titles (the root `title.template` already appends the brand); FAQ title "Prodily FAQ" or similar, answers rendered on the server, one concrete "how long does it take" answer computed from the compiled hours.
5. Compress the OG image only if a tool already in `package.json` can do it (`sharp`); otherwise list it for the owner.
6. Tests: sitemap has no `new Date()` for lessons; no `CourseUnit`; level mapping counts; FAQ HTML contains answers without client JS.
